# Generation contract 1.0

TTV owns GenerationPlan and GenerationResult. The editorial client owns GenerationRequest, PlanApproval and EditorialSelection. `edit_revision_id` is the selection ID. The five JSON Schemas use JSON Schema 2020-12. Clients pin the exact version and the raw-byte SHA-256 values in schema-hashes.json. Fixtures ending in `.invalid.json` must fail validation.

Canonical JSON is UTF-8 with Unicode characters unescaped, keys sorted by Unicode code point, no whitespace, finite JSON numbers, and integral numbers normalized to integers (including negative zero). Other numbers use Python JSON's shortest round-trip decimal representation. SHA-256 hashes are prefixed `sha256:`. Omit only the root `document_sha256` when computing a document hash. Defaults are never inserted before hashing. Documents are immutable; each ID and idempotency key binds its complete canonical bytes. Unknown costs are null; approval must explicitly allow them.

Scene `order` and shot `order` are explicit. A take's `clip_order` records its generated sequence. A selection's clip edit `order` defines editorial playback order and may deliberately reorder those clips in a new immutable edit revision. Array position alone carries no order. `trim_out_s` is the exclusive source out-point, not a duration removed from the tail. Takes list only complete candidates. Keyframe results contain scene keyframes and may have no clips or takes. Asset source_take_id records the take that supplied a boundary reference. Preview assets have role `scene_preview`.

HTTP: GET /v2/capabilities, POST /v2/plans, GET /v2/plans/{id}, POST /v2/jobs, GET /v2/jobs/{id}, GET /v2/jobs/{id}/result, POST /v2/jobs/{id}/cancel. Schemas are available at GET /v2/schemas/{name}. File mode: python -m api.generation_handoff --root PATH plan REQUEST.json, approve APPROVAL.json, run JOB_ID, status JOB_ID, result JOB_ID, cancel JOB_ID. The same service owns persistence, approval checks, execution, and terminal serialization in both transports.
